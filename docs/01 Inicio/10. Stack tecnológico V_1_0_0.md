## 1. Alternativas Evaluadas

| Criterio de Evaluación | Alternativa 1: Python / FastAPI + React + PostgreSQL + Leaflet | Alternativa 2: Node/Express + Vue.js + MongoDB | Alternativa 3: Java Spring Boot + Angular + PostgreSQL |
| --- | --- | --- | --- |

## 2. Justificación Técnica Formal

Se selecciona la **Alternativa 1: Python (FastAPI) + React + PostgreSQL (con extensión PostGIS) + Leaflet/OpenStreetMap** como stack tecnológico del proyecto, por las siguientes razones:

1. **Idoneidad directa para el núcleo del producto.** El valor central de EcoLogística Lima es el motor de optimización VRPTW/Green VRP. Python ofrece librerías especializadas y ampliamente validadas en investigación de operaciones (Google OR-Tools, DEAP para algoritmos genéticos, NetworkX), lo que reduce el riesgo técnico de construir el algoritmo desde cero, a diferencia de las Alternativas 2 y 3.

2. **Eficiencia y bajo consumo energético.** FastAPI es un framework asíncrono de bajo overhead, y el ecosistema científico de Python (NumPy, SciPy) está optimizado en C internamente para operaciones numéricas intensivas, lo que favorece el criterio de eco-diseño (menor consumo de CPU y, por tanto, menor huella de carbono del propio sistema) frente a la mayor carga de arranque y consumo de memoria de la JVM en la Alternativa 3.

3. **Modelo de datos geoespacial robusto.** PostgreSQL con la extensión PostGIS permite modelar direcciones, zonas de riesgo y rutas con tipos de datos y consultas geoespaciales nativas (distancias, polígonos de restricción vehicular), superando la madurez geoespacial de MongoDB para este caso de uso.

4. **Alineamiento con el perfil y la capacidad del equipo.** El equipo cuenta con experiencia previa en desarrollo full-stack y análisis de datos en Python, lo que reduce el riesgo de cronograma frente a adoptar Java Spring Boot, cuya curva de aprendizaje es significativamente mayor dentro del plazo académico de 14 semanas.

5. **Costo de infraestructura acotado al presupuesto.** El bajo consumo de recursos de FastAPI permite operar dentro de instancias cloud económicas, compatible con el techo presupuestal de S/ 500,000 para el MVP y S/ 120,000 anuales de operación definido en el Acta de Constitución.

6. **Cumplimiento de la restricción de código abierto.** Todas las tecnologías seleccionadas (FastAPI, React, PostgreSQL/PostGIS, Leaflet, OpenStreetMap) son de código abierto y sin costo de licenciamiento, conforme a la restricción C-01 del Registro de Supuestos y Restricciones.

**Combinación tecnológica final:** Backend en Python 3.12 con FastAPI; Frontend en React.js; Base de datos PostgreSQL 16 con extensión PostGIS; Caché de sesión con Redis; Mapa interactivo con Leaflet sobre capas de OpenStreetMap; motor de optimización implementado como módulo desacoplado en Python utilizando OR-Tools y/o DEAP según el tipo de metaheurística priorizada en cada iteración.
