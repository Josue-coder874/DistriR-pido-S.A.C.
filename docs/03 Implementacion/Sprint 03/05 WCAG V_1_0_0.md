# Evaluación de Accesibilidad Web (WCAG)

**Nombre del Proyecto:** EcoLogística Lima – DistriRápido S.A.C.
**Nivel de Conformidad Objetivo:** WCAG 2.1 Nivel AA
**Herramientas Utilizadas:** Lighthouse, revisión manual de teclado, etiquetas semánticas y contraste
**Versión:** V_1_0_0

## 1. Resumen de Accesibilidad por Principios

- **Perceptible:** Bajo revisión; el contraste debe verificarse con Lighthouse sobre una ejecución real.
- **Operable:** Bajo revisión; navegación por teclado disponible en controles nativos, pendiente prueba integral.
- **Comprensible:** Bajo revisión; etiquetas presentes; mensajes de estado deben revisarse con lector de pantalla.
- **Robusto:** Bajo revisión; componentes React deben validar semántica y nombres accesibles.

## 2. Hallazgos Principales y Correcciones

| Criterio | Problema detectado | Componente afectado | Solución aplicada |
|---|---|---|---|
| 1.3.1 Información y relaciones | La navegación modular puede quedar sin contexto semántico | Navegación principal | Se utiliza `<nav aria-label>` y botones accesibles |
| 2.4.6 Encabezados y etiquetas | Las vistas deben identificar su contenido | Dashboard, Pedidos, Rutas y Flota | Se añadieron títulos con atributos `aria-labelledby` |
| 3.2.2 Entrada | El formulario por defecto puede enviar sin confirmación visual | Pedidos | Se añadió mensaje de estado `role="status"` |
| 4.1.2 Nombre, función y valor | Los controles personalizados deben tener nombres | Navegación y selectores | Se mantienen controles HTML con etiquetas asociadas |

Antes del cierre debe ejecutarse Lighthouse sobre Login, Dashboard, Pedidos, Rutas y Flota con teclado y lector de pantalla.
