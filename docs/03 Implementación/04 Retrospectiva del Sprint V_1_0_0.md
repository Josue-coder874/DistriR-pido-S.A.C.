## ¿Qué aprendimos?

- La organización temprana del repositorio y la separación frontend/backend redujo la complejidad de desarrollo.
- La definición inicial de requisitos y alcance mínimo es clave para evitar retrabajos.
- El uso de herramientas de contenedores y entornos aislados facilita la configuración del proyecto.
- La validación constante con stakeholders permite ajustar la solución antes de invertir esfuerzo en funcionalidades innecesarias.

## ¿Qué estamos haciendo bien?

- Se logró una estructura base clara del proyecto.
- El equipo logró establecer una línea de trabajo coherente para backend, frontend y base de datos.
- La comunicación general del equipo fue suficiente para avanzar en la definición inicial del sistema.
- Se priorizaron los entregables mínimos funcionales del Sprint 1.

## ¿Qué podemos hacer mejor?

### Personas

- Mejorar la definición de roles y tareas específicas para cada miembro del equipo.
- Establecer reuniones más ágiles y frecuentes para revisar avances y bloquear impedimentos.
- Fortalecer la participación de todo el equipo en la validación técnica y funcional.

### Relaciones

- Definir canales de coordinación más claros para decisiones de arquitectura y alcance.
- Establecer un proceso más formal para compartir avances y observaciones entre áreas.
- Mejorar la retroalimentación con los stakeholders para alinear expectativas del producto.

### Procesos

- Reducir la ambigüedad del backlog durante la planificación del sprint.
- Incluir más criterios de aceptación por Historia de Usuario.
- Revisar el flujo de integración continua para evitar retrasos en la validación del sistema.

### Herramientas

- Usar tableros de trabajo más detallados y tickets con estimaciones claras.
- Mejorar la gestión de entornos de desarrollo y variables de configuración.
- Consolidar un conjunto de pruebas mínimas para validar cambios con mayor rapidez.

### Acciones a realizar

- Reforzar la separación de responsabilidades entre backend, frontend y QA.
- Completar la definición del modelo de datos con mayor nivel de detalle.
- Mejorar la integración bidireccional frontend-backend para la siguiente iteración.
- Implementar revisiones semanales de alcance y riesgos.
- Definir un plan de pruebas funcionales y de rendimiento del algoritmo de optimización.
